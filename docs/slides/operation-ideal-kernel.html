the only tool she has

git revert takes the whole commit

Git only knows one commit went in. It has no idea two different changes are sitting inside it.

the tension She needs to take back only the cache. Git doesn't work at that granularity — it never asked what was inside the commit, only what changed on disk.
why now

Git tracks bytes. LLMs write more of them, faster, in bigger commits.

So the first instinct is to log what the agent meant to do, alongside the commit. That doesn't survive.

Notes describe intent at the moment they're written. Code keeps changing underneath them. By the thirtieth commit, the notes describe a codebase that no longer exists — and nobody goes back to fix the notes.

how the split actually happens

How did sgt know one commit was two operations?

It never trusted the commit boundary. It looked at what each changed piece of code actually touches and uses.

robustness

Same change, same id — no matter how git rearranges the commits.

Ops are content-addressed: hashed from the change itself, not from where it happens to sit in history.

Three different commit shas, three different moments in git's history. sgt recognizes it's the same operation each time and never double-counts, never double-reverts.

the one case that needs a person

Two ops that both start from the same version.

A teammate was mid-edit on ApiClient at the same moment Mira's own quick follow-up touched it too.

a version builds on concurrent edit

Every other request in this deck resolved itself from the DAG. This is the one shape that can't: two ops with the same starting version. sgt surfaces it explicitly instead of silently interleaving the edits — a person (or agent) writes the reconciled version, and it lands only if it builds and passes tests.

naming groups of operations — the next layer

Why reverting the cache never touched the refactor.

Underneath, they were never the same feature. sgt is building a lens that names that grouping instead of leaving it implicit.

Two roots, not one commit. sgt revert <cache-op> only ever touched pricing-cache — checkout-client was never in scope. This tree isn't shipped yet: it's the layer sgt is building next on top of the kernel this deck has been describing.
