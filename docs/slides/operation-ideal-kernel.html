sgt · semi-git · the operation-ideal kernel

Your history as a set you can
re-select from.

Not commits bound to line-diffs — a graph of semantic operations on the functions, classes, and methods you actually reason about. A codebase state is just which operations are switched on.

Back out a feature. Roll one function back a week. Lift a fix onto a release. Every selection materializes to real, compilable code — no 3-way merge, no approximation.

02 · The problem

git records commit-bound line-diffs.
You think in features and functions.

Concretely: an AI agent adds a retry layer across 12 files in 40 commits, then GitHub squash-merges it to one. Now it's flaky and you want it gone — only it. git's only tools are a 3-way-merge conflict and blame archaeology, because the unit it tracks (a commit's diff) isn't the unit you're thinking in.

03 · The idea, in one picture

A state = which operations you've selected.
Each symbol has a version chain; you keep one tip per chain.

A downward-closed selection like this — one tip per symbol — is an order ideal. That's the whole model: a codebase state is a legal selection of operations.

04 · Reading the moves

Three moves — and what the arrows mean.

Because a state is a set, not a sequence, "the order of my commits" stops mattering. Revert and cherry-pick are ordinary set arithmetic — and the result is always a legal selection.

05 · Capture

The tangled agent commit → untangled into separate ops.

Now the retry wrapper and the rename are separate ops. You can revert one without touching the other — even though the agent jammed them into a single commit.

06 · Survives squash & rebase

The id is the content, not the sha.

This is why squash-merge and rebase — the things that shred git's history — don't faze sgt. Re-mining the same change just re-derives the same id and records another witnessing commit.

07 · Walkthrough — revert

Back out the retry layer = I \ ↑X

What's left materializes to compilable code, and revert mints no new op — it just moves ops out of the current selection. Change your mind? Add them back.

08 · Walkthrough — cherry-pick & pin

Lift a fix onto release = I ∪ ↓X · roll back one function = pin

"Roll slugify() back to last week" = pin that one chain to an older op; nothing else moves. All set operations, all exact.

09 · The only conflict

The one thing set algebra can't do:
two edits to the same function.

sgt never does a text 3-way merge — it makes the fork explicit and asks for one new op. This is the sole escape hatch where the algebra can't produce the bytes on its own.

10 · The feature lens

"What does this codebase contain?"
An overlay tree — pure metadata.

11 · How it works

One bidirectional lens: get ⇄ put.

What it bets on: the symbol, not the commit, is the right atom; a state is a set, not a sequence; ops are mined from real edits (sgt never writes your code); and git stays the one source of bytes. If those hold, every history question is a set operation.
