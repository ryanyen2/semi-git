# Handoff, 21 August 2026

Written to move this work to a second machine. It records what is finished, what is not, and the
commands and traps that are not obvious from the code. Everything here is about getting the study
runnable with a real participant.

The goal being served, in the words it was set in: the website has to be clear, the wording easy to
follow, the design controlled rather than open ended, and every step of the sgt condition has to be
not just correct but followable, because a participant can only act on what they understand.

## Finished

### One source for every sentence a participant reads

Each of the seven sheets in `docs/study/materials/` used to be a hand-typed second copy of copy that
also lives in the website. They had drifted. The printed welcome promised a session half an hour
longer than the website did, and the printed sgt practice sheet taught `sgt revert "Shipping"@2`
where the website had already fixed it to `sgt revert Shipping@2`.

All seven are now generated from `web/src/study/`:

```
cd web
npm run gen:materials    # writes docs/study/materials/*.md from src/study/
npm test                 # fails if a file on disk has drifted from the source
```

Both commands run `tests/schedule.test.ts`, which writes when `UPDATE_MATERIALS=1` and compares
otherwise. There is no separate generator binary on purpose: the old `scripts/gen-materials.ts`
called `vite-node`, which is not a dependency of `web/`, so it had never run in this checkout and
the drift test could only ever report a problem with no way to fix it.

Regenerating found three defects that drift had been hiding, all now fixed at the source:

- The practice step printed its opening instruction twice, in two different wordings, one directly
  under the other. It was the first line of both tutorial bodies and also a hand-written paragraph
  in `Tutorial.tsx`.
- `TASK_PREAMBLE` told the participant "three requests, about twenty minutes in total" against a
  block of five cards and 28 minutes. It had stayed that way since the two prediction trials were
  added. Counts now come from the request list.
- `DEBRIEF_MD` repeated the same stale claim.

Two clarity fixes landed on screen and on paper together: request sub-headings under a shared card
are numbered (request 3 opens with "One correction to the last request" and had nothing to anchor
to), and joined card titles no longer capitalise mid-sentence.

### The tree's root is the repository, not a subsystem

`sgt log --tree` and `sgt log --map` both headed the study's practice repo with `README.md add_item
remove_item total cart.py`. The root node holds every alive symbol by construction, so the labeler
was being asked to name the whole repository, which is the one thing its prompt tells it not to
produce. With no credential it fell back to assembling member names.

The root is now named after the repository's own directory (`sgt/lens/tree.py`, in `label_tree`).
It costs no LLM call and does not change between rebuilds. The map's summary line stopped counting
the root as a subsystem, so a repo with no subsystems no longer claims one.

### Title case that reads like a person wrote it

`Catalog And Search` was the second row of the confplan tree, on the first screen a participant
meets. Both prompts in `sgt/lens/label.py` now ask for lowercase joining words, and
`_normalise_title_case` enforces it on every accepted label, because the model answers each cluster
independently and the instruction held for most of them and not all.

### Other fixes

- `scripts/make-practice-repo.sh <dest> sgt` with no bundle root printed "Practice repo at <dest>"
  over a plain git repository with no `.sgt` in it. The sgt build and all of its checks sat behind a
  guard that also required the bundle root. It now names what is missing and exits 1.
- The `(s)` plural placeholders are gone from `sgt/api.py`'s next-action labels. `sgt log` still
  prints `6452 saved edit(s)` and `make-practice-repo.sh` still prints `23 symbol(s) touched`, so
  the sweep is not finished. See below.
- Em dashes are out of participant prose. The NASA-TLX item wording in `instruments.ts` keeps its
  own, deliberately: instrument fidelity beats the house style rule.
- The answer recap on a finished card showed a bare dash for a question left blank. It says "Not
  answered".
- VS Code extension at 0.3.0.

## Not finished

In the order it should be picked up.

### 1. Walk the sgt condition end to end, judging clarity

This is the item the rest is gated on. The point is not that the commands work. It is that a
participant who has had ten minutes of practice can read what comes back, know what it means, and
know what a next action would do.

Where it got to: the confplan tree and `sgt now` are walked. The practice sheet is walked as far as
step 2. Steps 3 to 8 of the practice sheet, and the five task cards, are not.

Build a practice repo to walk against without a full bundle:

```
B=/tmp/fakebundle; V=$PWD/.venv
mkdir -p $B/bin $B/toolenv/bin
printf '#!/bin/sh\nexec "%s/bin/sgt" "$@"\n' "$V" > $B/bin/sgt
printf '#!/bin/sh\nexec "%s/bin/python" "$@"\n' "$V" > $B/toolenv/bin/python
chmod +x $B/bin/sgt $B/toolenv/bin/python
bash scripts/make-practice-repo.sh /tmp/practice-sgt sgt $B
```

Use a wrapper script for `toolenv/bin/python`, not a symlink. A symlink to the venv's python makes
python resolve a venv root that has no `pyvenv.cfg`, so `import sgt` fails and the script's hard
gate refuses to ship the copy. That refusal is correct behaviour and worth seeing once.

The practice sheet quotes exact numbers that have to hold on every machine: five things in two files
for `sgt show "Shipping"`, four saves that built it, 14 edits across 2 files for the `Receipts`
preview, `3 other features unchanged`, nine tests passing after the revert and eleven after the
undo, and the literal save id `44da4ad`. The commit dates in `make-practice-repo.sh` are pinned, so
that sha is deterministic and it does resolve. The rest are unverified.

Open findings from the part that is walked:

- `Command Parsing` (03eb57d7 in confplan) is clustered under `Admission Queue`, where it does not
  belong, and its label changes on every rebuild.
- Feature ids appear in three formats in one tree: `af-m0530`, `00803624`, `m8068d4e`.
- The tree mixes synthesized Title Case labels with verbatim lowercase commit subjects and nothing
  tells the reader which kind of name they are looking at. That mix is `subject_label`'s deliberate
  design, so changing it is a design decision rather than a fix.
- `sgt now` on a clean repo prints `→ next  nothing pending`, which is true and useless to someone
  who has just arrived and wants to know how to look around.
- On the real repo, `sgt log --tree` shows `Intent Segmentation Analysis` nested inside a node of
  the same name inside a node of the same name. Single-child internal nodes are collapsed as of the
  fix earlier in this session, so this is probably a tree built before it. Confirm with a rebuild on
  a copy, not on a live repo.

### 2. Decide the labeler's backend

The study machines are meant to use an Anthropic key. `sgt` reaches the model through the OpenAI
Responses API, and Anthropic's OpenAI-compatible endpoint does not implement it, so "swap the key"
is not available. Either keep the proxy route through `ANTHROPIC_AUTH_TOKEN`, or add a native
Anthropic path to `sgt/config.py`. Until this is settled, a participant's repo gets real feature
names only because the bundle build made the LLM calls on the build machine.

### 3. Rebuild the four bundles and deploy

`scripts/publish-study.sh:39` refuses to build while `sgt/`, `pyproject.toml`, or `editor/vscode/`
is dirty, so it needs a clean tree. Then publish the website to Firebase. Deploy last, after item 1.

  20 alive, 3 tombstoned, 20 placed in 4 leaf feature(s)`. Same `(s)` class as the rest of the

## Traps

- Run pytest focused per file or per directory. The whole suite takes over half an hour. Do not add
  xdist and do not weaken a test to make it faster.
- Never mutate `~/repos/sgt-study/confplan` or `~/repos/sgt-study/coursecraft`. They are the
  fixtures. Copy them to `/tmp` and work there.
- Do not run `sgt revert` on this repo. Reads (`sgt log`, `--json`, `--map`) are fine.
- The bundle build rebuilds the tree on its staged copy, so the fixtures' own sv=3 trees never
  ship. A participant sees sv=4 output. Walk a rebuilt copy, not the fixture.
- `/tmp/sgt-e2e` and `/tmp/sgt-walk` on the old laptop hold copied `.env` files. Delete them.
