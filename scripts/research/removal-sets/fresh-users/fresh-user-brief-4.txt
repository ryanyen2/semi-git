=== PAGE 1: what the tool is, as a user is told ===

The tool sits on top of git. For every save (a commit, or one request to a coding agent) it keeps what that save did to each function or other top-level definition. One save's change to one definition is called a step.

Later work can stand on a step in three ways, and the tool always names which:
  - "uses it": code that remains uses a definition the step created;
  - "changed it later": a later request changed a definition the step created;
  - "rewrote the same lines": a later request rewrote lines the step wrote. The tool cannot pull these two apart by itself, because the same lines carry both changes.

You do not tell the tool "undo this request". You ask what it would take to make a request gone, and it answers with up to three options. Nothing happens until you pick one.
  - Option 1 takes out only the steps that nothing else stands on. Steps that something stands on are held in place, whole.
  - Option 2 takes out the complete set: the request and everything that stands on it. That set is what the tool calls a feature.
  - Option 3 leaves the held part to you or your coding agent to remove by hand, as a new save; the tool tells you where it is and which other requests must keep working.

For every option the tool first says whether the request would be gone for a visitor. It knows what the request showed a visitor when it was added, and it runs what the project itself renders, before and after, to see whether that is still shown and what else changes. Then it says what happens in the code. It recommends one option and says why. No option leaves the program failing the project's own check (here check.py, which renders every page), and the tool warns when an option changes that check itself.

Nothing in git history is rewritten. The result is an ordinary change in your working tree, which you commit like any other. Files the tool cannot split into definitions (templates, configuration) are treated as one piece each.

Bringing a request back works the same way in reverse. If you edited in the meantime, edits to different lines of the same function are combined automatically. Where your edit and the returning step replaced the same lines, the tool shows both versions side by side and you pick one or write a combined one; until you do, the tool does not let you commit.
