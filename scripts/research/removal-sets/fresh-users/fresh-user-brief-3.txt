=== PAGE 1: what the tool is, as a user is told ===

The tool sits on top of git. For every save (a commit, or one request to a coding agent) it keeps what that save did to each function or other top-level definition. One save's change to one definition is called a step.

You can take any save out, and bring it back later. Taking a save out undoes each of its steps, except the steps that later work stands on: those are held in place. A step is held whole or goes whole. Later work stands on a step in one of three ways, and the preview names which:
  - "uses it": code that remains uses a definition the step created;
  - "changed it later": a later request changed a definition the step created;
  - "rewrote the same lines": a later request rewrote lines the step wrote. The tool cannot pull these two apart by itself, because the same lines carry both.

Before anything happens the tool shows a preview. It starts with what a visitor would notice: the tool runs what the project itself renders, before and after, and reports the difference. Then it says what happens in the code. The tool never leaves the program in a state that fails the project's own check (here check.py, which renders every page); if undoing a step would break the check, that step is held too.

When something is held, the preview shows the complete set: what else would have to come out for the thing to be gone entirely, counted in whole steps of named requests, with what a visitor would see after that. It warns when that set changes the check itself. You then choose: leave it as the preview shows, take out the complete set, or remove the leftover by hand or with your coding agent (that is a new save).

A feature is the smallest set of steps, starting from a request, a function or a line, that nothing outside the set stands on. Taking out such a set removes the thing completely.

Nothing in git history is rewritten. The result is an ordinary change in your working tree, which you commit like any other. Files the tool cannot split into definitions (templates, configuration) are treated as one piece each.

If you keep editing while something is out and later bring it back: edits to different lines of the same function are combined automatically. Where your edit and the returning step replaced the same lines, the tool keeps the version you have now and sets the returning one aside. It says so in the preview, and the save stays marked "partly back" in the status and in the commit message until you pick the other version or write a combined one. There is no state with conflict markers.
