=== PAGE 1: what the tool is, as a user is told ===

The tool sits on top of git. For every save (a commit, or one request to a coding agent) it keeps what that save did to each function or other top-level definition. One save's change to one definition is called a step.

For each step it also records what the step stands on:
  - the earlier steps whose lines it rewrote,
  - the definitions its code uses,
  - the definitions somebody else created and it changed.

You can switch any save off, and later on again. When a save is off, each of its steps is undone, unless something that remains stands on it. A step stays whole or goes whole. Before anything happens the tool lists what goes, what stays and why. It does not leave the program in a state that fails the project's check (compiler or tests): if undoing a step would break the program, that step stays and is listed with the reason.

For anything that stays you can choose "take it out too". That also takes out what stands on it, and the tool lists those first.

A feature is not a folder or a label. It is a set of steps that nothing outside it stands on, for example three requests that built on each other. You get one by pointing at a request, a function or a line and asking what stands on it.

If you keep editing while something is off and later switch it back on: edits to different lines of the same function are combined automatically. Where your edit and the returning step replaced the same lines, the tool keeps the version you have now, sets the returning one aside and lists it. You can switch to the other version or write a combined one. There is no state with conflict markers.
