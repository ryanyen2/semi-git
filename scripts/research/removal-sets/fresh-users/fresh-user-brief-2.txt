=== PAGE 1: what the tool is, as a user is told ===

The tool sits on top of git. For every save (a commit, or one request to a coding agent) it keeps what that save did to each function or other top-level definition. One save's change to one definition is called a step.

For each step it records what later work stands on it. There are three ways:
  - later code uses a definition the step created,
  - a later step changed a definition the step created,
  - a later step was written on top of the step's change (it rewrote some of the same lines).

You can take any save out, and bring it back later. Taking a save out undoes each of its steps, except the steps that something remaining stands on: those are held in place. A step is held whole or goes whole. The tool shows a preview first, and the preview starts with a verdict: removed completely, only partly removed, or not removed.

The preview also says what the project's own check observes before and after. The check is whatever command the project uses to tell that it works; here it is check.py, which renders every page. The tool never leaves the program in a state that fails that check.

When something is held, the preview shows which request holds it and how, and it shows the set that would remove the thing completely together with what that costs the other requests. You then choose: leave it partly removed, take out the complete set, or hand the leftover to yourself or your coding agent to remove by hand (that becomes a new save).

A feature is the smallest set of steps around a starting point (a request, a function, a line) that nothing outside the set stands on. "Removed completely" means you took out such a set.

Nothing in git history is rewritten. The result is an ordinary change in your working tree, which you commit like any other.

If you keep editing while something is out and later bring it back: edits to different lines of the same function are combined automatically. Where your edit and the returning step replaced the same lines, the tool keeps the version you have now, sets the returning one aside, lists it, and says the save is only partly back. You can switch to the other version or write a combined one. There is no state with conflict markers.
